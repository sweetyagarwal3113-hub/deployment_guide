Module 1: What is AiSensy & The WhatsApp Ecosystem
1. What is AiSensy?

AiSensy is a WhatsApp business communication and marketing automation platform built on top of the official WhatsApp Business Platform. It empowers businesses to manage bulk broadcasts, customer support, automated chatbot flows, AI agents, audience segmentation, and API-driven transactional notifications.

Simple Definition: AiSensy is a platform layer that makes it easy for businesses to automate, manage, and scale WhatsApp communication using the official WhatsApp Business API without building complex infrastructure from scratch.

4. Platform vs Direct API vs WhatsApp
❓ Is AiSensy an API?

Not strictly. AiSensy is a full SaaS platform that includes REST APIs alongside visual dashboards, bot builders, and inboxes.

❓ Is it a WhatsApp Replacement?

No. AiSensy relies entirely on Meta's underlying WhatsApp Business Account (WABA) infrastructure and policy guidelines.

Module 4: WhatsApp Templates, 24-Hr Window & Meta Policies
1. WhatsApp Message Templates

Meta strictly controls business-initiated communications. To initiate a conversation with a user, businesses must use a pre-approved Template Message containing placeholder variables (e.g., customer name, order number, delivery date).

2. Template Approval Lifecycle
Create Template in Dashboard
➔
Submit to Meta Review
➔
Meta Verification
➔
Approved (Ready for Campaigns)
3. The 24-Hour Customer Service Window
Critical Rule: When a user sends a message to your WhatsApp number, a 24-hour service window opens.
  • Inside 24-hr Window: Business can send free-form text, images, and custom replies without pre-approved templates. Every incoming user message resets the 24-hour timer.
  • Outside 24-hr Window: Free-form messaging is blocked by Meta. Business can only send pre-approved Template Messages.

3. Idempotency & Duplicate Prevention Strategy

To prevent sending duplicate WhatsApp messages during server restarts or cron retries, maintain a separate execution log table:

Idempotency Strategy: Create a unique database composite constraint on user_id + notification_type + scheduled_date. Before dispatching any outbound message request to AiSensy, query the execution log. If a record exists, skip execution.
SECURITY RULE: Keep API secrets inside server-side environment variables (.env). Never expose API credentials inside client-side bundles.

Module 6: Webhooks, Event Handling & API vs Webhook
1. What is a Webhook?

A Webhook is an HTTP POST notification sent by AiSensy/Meta to your backend server whenever an asynchronous event occurs (e.g., message delivered, read receipt, or user reply).

User Action / Message Status
➔
Meta Cloud API
➔
AiSensy Webhook Hub
➔
Your Backend Webhook Endpoint
2. Supported Webhook Event Statuses
📤 `sent`

Message successfully accepted by Meta servers.

📱 `delivered`

Message delivered to the recipient's phone device.

👀 `read`

Recipient opened the chat and read the message.

💬 `incoming_message`

Customer replied with text, image, or button click.
